# BackendTZ

Backend API для системи бронювання конференц-кімнат (Conference Room Booking API), реалізований на **ASP.NET Core (.NET 10)**.

## Бізнес-задача

Компанія здає в оренду конференц-зали для проведення заходів. Клієнти повинні мати можливість:

- знайти вільні зали на потрібну дату/час за необхідною місткістю;
- забронювати обрану залу та за потреби додати додаткові послуги (проєктор, Wi-Fi, звукове обладнання тощо);
- отримати підсумкову вартість бронювання, яка залежить від часу доби оренди та обраних послуг.

Адміністратори системи керують залами та послугами, а також отримують звіти по завантаженості залів, популярності послуг і доходу компанії.

## Опис

Проєкт надає REST API для управління бронюванням кімнат, послугами, звітністю та автентифікацією користувачів. Використовує шаблони Repository / Unit of Work, JWT-автентифікацію з refresh-токенами та фонові сервіси для очищення токенів і синхронізації доступності кімнат.

## Ціноутворення (PricingService)

Вартість бронювання розраховується `PricingService` на основі базової погодинної ставки залу (`Room.BaseHourlyRate`) з поправкою на час доби. Період бронювання розбивається на погодинні відрізки, і до кожного відрізка застосовується свій коефіцієнт залежно від того, у яку часову смугу він потрапляє:

| Часова смуга      | Період        | Коригування     |
|-------------------|---------------|------------------|
| Ранкові години     | 06:00–09:00   | знижка **-10%**  |
| Стандартні години  | 09:00–12:00, 14:00–18:00 | без змін (базова ставка) |
| Пікові години      | 12:00–14:00   | націнка **+15%** |
| Вечірні години     | 18:00–23:00   | знижка **-20%**  |
| Решта часу         | 23:00–06:00   | без змін (базова ставка) |

Таким чином, якщо бронювання охоплює декілька смуг (наприклад, 08:00–15:00), кожна година оплачується за своїм коефіцієнтом, а не за єдиною ставкою для всього періоду.

До розрахованої вартості оренди додається вартість усіх обраних додаткових послуг (`Service.Price`). Підсумкова відповідь (`CostBreakdown`) містить базову вартість, суму коригувань за час доби, вартість послуг та загальну суму.

## Seed-дані

При старті застосунку в середовищі **Development** автоматично виконуються міграції бази даних та наповнення її початковими даними (`DataSeeder`), якщо таблиці ще порожні. Окремої команди для цього не потрібно — достатньо запустити проєкт.

Початкові дані:

**Послуги:**
| Назва     | Ціна    |
|-----------|---------|
| Проєктор  | 500 грн |
| Wi-Fi     | 300 грн |
| Звук      | 700 грн |

**Зали:**
| Назва  | Місткість | Базова ставка/год | Доступні послуги      |
|--------|-----------|--------------------|------------------------|
| Зал A  | 50        | 2000 грн           | Проєктор, Wi-Fi        |
| Зал B  | 100       | 3500 грн           | Проєктор, Wi-Fi, Звук  |
| Зал C  | 30        | 1500 грн           | Wi-Fi                  |

## Технології

- ASP.NET Core Web API (.NET 10)
- Entity Framework Core + SQLite (`bookings.db`)
- JWT Bearer автентифікація (access + refresh токени)
- Swagger / OpenAPI (Swashbuckle)
- DotNetEnv (`.env`) для конфіденційних налаштувань
- Фонові сервіси (`IHostedService`): очищення прострочених refresh-токенів, синхронізація доступності кімнат

SQLite був використаний для швидкого переходу до роботи без додаткового налаштування бази даних.
В більших проектах із більшими базами даних краще використовува PostgreSQL та подібні масштабовані рішення.

## Архітектура

- **Controllers** — API-контролери: `AuthController`, `BookingController`, `RoomsController`, `ServicesController`, `ReportController`
- **Services** — бізнес-логіка (`AuthService`, `BookingManagementService`, `RoomManagementService`, `ServiceManagementService`, `PricingService`, `ReportService`, `JwtTokenGenerator`, `RefreshTokenService`)
- **Repositories** — доступ до даних через `IRepository<T>` та `IUnitOfWork`
- **Data** — `BookingDbContext`, конфігурації сутностей EF Core, міграції, seed-дані (`DataSeeder`)
- **Entities** — доменні моделі: `User`, `Room`, `Booking`, `Service`, `BookingService`, `RoomService`, `RefreshToken`
- **DTOs** — об'єкти запитів/відповідей (`Requests`/`Responses`)
- **Middleware** — глобальна обробка винятків (`ExceptionHandlingMiddleware`)
- **Extensions** — реєстрація сервісів, CORS, JWT, Swagger, seed-даних

## Основні можливості API

- **Auth**: реєстрація, вхід, вихід, оновлення токена (access/refresh, refresh-токен зберігається в cookie)
- **Bookings**: створення, зміна, підтвердження, скасування та отримання бронювань
- **Rooms**: управління конференц-кімнатами, пошук вільних залів за датою/місткістю
- **Services**: додаткові послуги, що можна замовити разом із бронюванням
- **Reports**: звіти по доходу, завантаженості залів, популярності залів/послуг та статистиці бронювань

### Ключові ендпоінти

| Метод | Маршрут                        | Опис                                        |
|-------|---------------------------------|---------------------------------------------|
| POST  | `/api/auth/register`            | Реєстрація нового користувача               |
| POST  | `/api/auth/login`                | Вхід та отримання access/refresh токенів    |
| POST  | `/api/rooms/find-available`      | Пошук вільних залів за датою та місткістю   |
| POST  | `/api/bookings/create`           | Створення бронювання                        |
| POST  | `/api/bookings/confirm/{id}`     | Підтвердження бронювання                    |
| POST  | `/api/reports/revenue`           | Звіт по доходу компанії                     |

Повний перелік ендпоінтів з описом параметрів та моделей запитів/відповідей — у Swagger UI (див. нижче).

## Запуск проєкту

1. Створіть файл `.env` у корені проєкту з такими змінними:
   ```env
   AppSettings__AccessToken=<секретний ключ для JWT>
   AppSettings__Issuer=<issuer>
   AppSettings__Audience=<audience>
   AppSettings__ExpirationTime=<час дії access-токена (хв)>
   AppSettings__RefreshTokenExpirationTime=<час дії refresh-токена (дні)>
   AppSettings__RoomAvailabilitySync=<інтервал синхронізації>
   ```
2. База даних SQLite (`bookings.db`) вказана в `appsettings.json` (`ConnectionStrings:DefaultConnection = Data Source=bookings.db`) і не потребує додаткового налаштування — файл створюється автоматично поруч із проєктом. За потреби застосувати міграції вручну:
   ```powershell
   dotnet ef database update
   ```
3. Запустіть застосунок:
   ```powershell
   dotnet run
   ```
   При першому запуску в режимі Development автоматично застосуються міграції та наповняться seed-дані (зали та послуги, див. розділ "Seed-дані").
4. Відкрийте Swagger UI за адресою (порт може відрізнятися, дивіться вивід консолі або `Properties/launchSettings.json`):
   ```
   https://localhost:{port}/swagger
   ```
   Наприклад: `https://localhost:7295/swagger`.

## Конфігурація

Основні налаштування знаходяться у `appsettings.json`:
- `ConnectionStrings:DefaultConnection` — рядок підключення до SQLite бази даних
- `Cors:AllowedOrigins` — дозволені origin-и для CORS
- `AppSettings` — параметри JWT та фонових сервісів (значення підставляються зі змінних середовища `.env`)
